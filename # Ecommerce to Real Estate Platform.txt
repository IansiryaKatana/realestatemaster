# Ecommerce to Real Estate Platform Conversion Guide

## 1. Project Objective

Convert the existing ecommerce platform into a full real estate rental and sales platform.

The current system already includes the full codebase, database schema, workflows, seeded data, admin management, user accounts, and product-based frontend structure. The goal is to repurpose the existing ecommerce logic into a real estate workflow where products become properties, product categories become property types or locations, and purchase/rental actions become viewing, rent, buy, contract, payment, and handover workflows.

The main development focus is to update:

* Frontend copy and imagery
* Product terminology into property terminology
* Product cards and property detail pages
* Admin property management fields
* Agent assignment and commission logic
* Viewing, declaration, contract, payment, and handover workflows
* Real estate agency information
* Notifications between clients, agents, and admin
* Contract generation and upload/review flow

# 3. Property Types

The platform should support both rental and sale properties.

## Rental Properties

Rental property cards should have the following primary actions:

* Book a Viewing
* Rent Now

Rental property workflows should include viewing, client declaration, agent approval, contract request, contract generation, signed contract upload, payment, and handover.

## Sale Properties

Sale property cards should have the following primary actions:

* Book a Viewing
* Buy Now

Sale property workflows should follow a similar structure but use buyer/sale-specific wording instead of tenant/rental wording.

1. Hero section with map background

* Message

# 9. Agent Commission Logic

Agents should be able to define a default commission amount or commission percentage.

## Commission Requirements

* Each agent can set a default commission.
* When creating or editing a property, the commission field should be visible.
* The property-level commission can use the agent’s default commission or be manually changed.
* Commission can be negotiated up or down per property or per transaction.
* Commission should appear clearly in the client payment breakdown before payment.
* Commission should be included in invoice generation.

# 13. Viewing Workflow

## Step 1: Client Books a Viewing

The client selects a property and books a viewing.

The system should:

* Save the viewing request
* Notify the assigned agent
* Notify admin if required
* Show the viewing status in the client account
* Show the viewing request in the agent account

## Step 2: Viewing Completed

The agent can mark the viewing as:

* Pending
* Scheduled
* Completed
* Cancelled
* No show

After the viewing is completed, the client should be able to declare whether they want to proceed.

---

# 14. Client Declaration Workflow

After viewing a property, the client must declare whether they want to proceed.

## Client Declaration Options

* Proceed
* Not proceed
* Need more information

## If Client Declares “Proceed”

The system should:

* Notify the assigned agent
* Update the transaction status
* Allow the agent to review and approve the next step

## If Client Declares “Not Proceed”

The system should:

* Close or archive the transaction
* Notify the agent
* Keep the record in the client and agent dashboards

---

# 15. Agent Approval Workflow

When a client declares they want to proceed, the assigned agent receives a notification.

The agent can then:

* Approve the client to proceed
* Request more information
* Reject the request
* Add internal notes

Once approved, the client can request a contract.

---

# 16. Contract Request Workflow

After agent approval, the client should be able to request a contract.

## Contract Request Logic

When the client requests a contract:

* Notify the assigned agent.
* Show the request inside the agent dashboard.
* Attach the request to the relevant property and client.
* Mark the contract status as requested.

---

# 18. Signed Contract Upload Workflow

After the agent generates and sends the contract:

1. Client downloads the contract.
2. Client signs the contract.
3. Client uploads the signed contract in their account.
4. Agent receives a notification.
5. Agent reviews the signed contract.
6. Agent approves or rejects the uploaded contract.

## Agent Review Options

* Approve contract
* Reject contract
* Request re-upload
* Add review notes

If approved, the transaction moves to payment pending.

---

# 28. Complete User Journey

## Rental Journey

1. Client views rental property.
2. Client books a viewing.
3. Assigned agent is notified.
4. Agent confirms or manages viewing.
5. Client views property.
6. Client declares whether they want to proceed.
7. Agent reviews and approves.
8. Client requests contract.
9. Agent generates contract.
10. Client downloads, signs, and uploads contract.
11. Agent reviews signed contract.
12. Agent approves contract.
13. Client pays rent, security deposit, commission, and other charges.
14. Invoice is generated.
15. Agent arranges handover.
16. Client receives handover details.
17. Agent marks handover complete.
18. Transaction is completed.

## Sale Journey

1. Client views sale property.
2. Client books a viewing.
3. Assigned agent is notified.
4. Agent confirms or manages viewing.
5. Client views property.
6. Client declares whether they want to proceed.
7. Agent reviews and approves.
8. Client requests contract or purchase agreement.
9. Agent generates contract.
10. Client downloads, signs, and uploads contract.
11. Agent reviews signed contract.
12. Agent approves contract.
13. Client pays required deposit, commission, and other charges.
14. Invoice is generated.
15. Agent arranges next steps for sale completion or handover.
16. Transaction is completed or moved to external legal/transfer process.

# 29. Development Instruction

Do not rebuild the platform from scratch.

Use the existing ecommerce codebase, workflows, authentication, admin structure, database schema, seeded data, payment logic, invoice logic, and user account system as the foundation.

Refactor the system into a real estate platform by renaming, extending, and adapting existing modules.

The platform should feel like a complete real estate website, not an ecommerce site with changed labels.

Every workflow must be clear, role-based, traceable, and visible to the correct user.

The final platform should support property discovery, viewing bookings, agent-managed approvals, contract generation, signed contract review, payment, invoice generation, and handover completion.

---

* Add rental and sale properties

* Manage property locations and maps

* Let clients download, sign, and upload contracts
